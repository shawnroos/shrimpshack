## Residuals

### R1 — P2 — the TodoWrite matcher cannot fire in agent/SDK/team sessions
`plugins/reflect/.claude/hooks/hooks.json`

`TodoWrite` and `TaskCreate` both exist in build 2.1.226, and which set a session
exposes varies by session shape. Agent/SDK/team sessions expose
`TaskCreate`/`TaskUpdate`/`TaskList` and **no `TodoWrite`** — the session that built
this branch is one of them. So U0 restores the all-todos-done trigger for
interactive sessions only, and the plan's own build sessions are among those where
it cannot fire.

Not applied: widening to a `TaskUpdate` matcher is new behavior beyond U0's scope.
Fix: add a `TaskUpdate` matcher with its own jq predicate, or match
`TodoWrite|TaskUpdate` with a shape-tolerant one.

### R3 — P3 — `scope.py`'s `repo_root` is wrong for submodules
`plugins/reflect/scripts/scoped-memory/scope.py:52-66`

Demonstrated on a real submodule: a submodule's `.git` is a **file** pointing at
`<super>/.git/modules/<name>`. That path ends in neither `/.git` nor a `.git`
basename, so both fold branches fall through and the resulting scope slug names a
path **inside** `.git` — neither the submodule checkout nor the superproject.

```
/…/sm/super/sub -> repo_root= /…/sm/super/.git/modules/sub
                   slug= …-sm-super-.git-modules-sub
```

Pre-existing, unrelated to this branch, and low impact (no submodules in play here).
Note separately that reverting the `--show-toplevel` change earlier in this branch
was still **correct** — that change broke the worktree→parent fold, which is a
different and much more common case.

### R4 — P2 — one harness block depends on globally-stateful qmd
`plugins/reflect/tests/harness.sh` (qmd reconcile block)

Mitigated in `8286190` but not eliminated. qmd's collection state is **global** on
this machine (13 collections visible repo-wide; `claude-handoffs` already existed
from an earlier `/reflect`), so the block's `qmd init` in a temp dir isolates
nothing and concurrent harness runs share one daemon. The block now probes for a
responsive qmd before running and reports `skip` when qmd stops answering
mid-block, rather than recording "could not ask" as "the answer is no".

Residual: with a genuinely wedged qmd these assertions skip rather than run, so
their coverage is conditional on the daemon's mood. Fix properly by stubbing qmd for
this block, or by isolating qmd state per run if it ever gains a home/config
override.

### R5 — process — four false-positive assertions of one shape, authored by me
`plugins/reflect/tests/harness.sh`

Four assertions I wrote during this run failed against **correct** code because they
grepped for a *word* the correct implementation legitimately contains:

- `recall_floor` — matched a docstring explaining why the qmd floor must not be reused
- `TOOL_INPUT` — matched a comment explaining that the variable does not exist
- `qmd` — matched a source-layer label in the CLI's own output
- `subprocess` — matched a comment reading *"no subprocess"*

The better an implementer documents a trap, the more likely this style of assertion
punishes them for it. All four were rewritten to assert imports, calls, and process
launches, with comments stripped. Worth a memory: **assert behavior, never
vocabulary.**

## Process notes worth carrying

- **A clean auto-merge on a shared append-only file is the dangerous case.** I told
  `u10` that `harness.sh` was free and then edited it myself for review fixes. Both
  edit sets landed in different sections and nothing was clobbered — verified by
  inspection and a full run — but that is exactly the hazard the plan warns about,
  and I caused it. Later batches avoided it by having each worker hand me its
  harness block instead of writing the file.

- **Worker reports do not always reach the orchestrator.** Several subagents went
  idle without their final message arriving. The work was recoverable from the tree,
  but *verification evidence* — which mutation was tried, what red failure was seen —
  exists only in the worker's report and cannot be reconstructed from a diff. Where
  that happened I re-derived it by mutation-testing myself rather than assuming.
