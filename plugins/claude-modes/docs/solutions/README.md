# docs/solutions/

This directory holds documented solutions to past problems we hit
while building, operating, and extending `claude-modes`. Bugs and
their root causes, architecture patterns that worked, design patterns
worth carrying forward, tooling decisions and their rationale,
naming and structural conventions, and workflow practices the team
landed on after iteration.

The directory is seeded empty at the U13 milestone of V2. Future
learnings captured by `/ce-compound` and adjacent compound-engineering
workflows during V2.0.x and V2.1 development land here, organized by
subdirectory when categories emerge (e.g., `bugs/`, `architecture-patterns/`,
`workflow/`).

Each entry should be timestamped (`YYYY-MM-DD-<slug>.md`), state the
problem, the root cause, the resolution, and the lesson for next time.
Brief is fine — the file's value is being findable, not exhaustive.
